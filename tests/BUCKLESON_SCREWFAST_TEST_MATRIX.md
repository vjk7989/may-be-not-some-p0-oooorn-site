# Buckleson ScrewFast Rebuild Test Matrix

## Purpose and release rule

This matrix is the independent acceptance contract for replacing the current
site with the English-only ScrewFast Astro template pinned to upstream commit
`54d1daa00214deb5b97613d2a61cf9f997df2218` and adapting its content and media
to Buckleson. It is intentionally bounded to the public static website, its
preserved template interactions, and GitHub Pages deployment. Backend forms,
authentication, payments, a CMS, and runtime APIs are out of scope.

Release requires every applicable automated gate below to pass without retries,
plus the listed desktop, tablet, and mobile browser checks. A failed gate blocks
dependent work until an independent failure analysis classifies the defect as
production code, test, fixture, or environment; a valid test must not be
weakened or deleted to obtain a pass.

## Required fixtures

- The source tree after import and the generated `dist/` directory.
- The pinned ScrewFast upstream commit identifier and retained MIT license.
- Buckleson source content recoverable from commit `1e796f9`.
- Byte-preserved Buckleson and Hyper-0x logos and the four approved cinematic
  Buckleson images recovered from Git history, with expected SHA-256 hashes.
- Two build configurations: local root (`/`) and the configured GitHub Pages
  repository base path.
- Browser viewports: desktop `1440x1000`, tablet `768x1024`, and mobile
  `390x844`; a reduced-motion context; a keyboard-only context; and JavaScript
  disabled where native/static fallback is expected.

## Explicit applicability decisions

| Category                     | Applicability              | Reason                                                                                                                                                                                                                                      |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concurrency                  | N/A                        | The deliverable is a pre-rendered static site with UI-only forms and no shared mutable server state, transaction, queue, or concurrent write path. Parallel build-worker behavior is dependency-owned and not a Buckleson feature boundary. |
| Time                         | N/A beyond content parsing | No runtime timer, expiry, scheduling, polling, or time-dependent business behavior is in scope. Dates in article/frontmatter inputs are still covered by E-01, but wall-clock manipulation is not required.                                 |
| Randomness                   | N/A                        | Routes, content, image selection, motion parameters, and build output must be deterministic; the implementation has no random identifier, sample, experiment, or cryptographic-randomness requirement.                                      |
| Runtime persistence          | Limited                    | Only existing template preferences such as theme or banner dismissal may use browser-local state. There is no account, database, server session, or cross-device persistence.                                                               |
| Authentication/authorization | N/A                        | The public site has no login, protected route, user account, or privileged operation. Product copy about agent credentials does not create a website credential system.                                                                     |
| Payments/digital assets      | N/A and prohibited         | Hyper Wallet is explicitly not a payment or digital-asset custody product; the site must not implement or imply either workflow.                                                                                                            |

## Recommended execution order

1. Run provenance, source hygiene, hash, content, route, localization, link,
   claim, workflow, and negative-fixture validators.
2. Run formatting, `astro check`, production/minified builds for root and Pages
   base configurations, then crawl both generated outputs.
3. Serve the Pages-base build locally and run the preserved template smoke suite
   plus focused Playwright state-transition tests with retries disabled.
4. Run the full responsive, keyboard, reduced-motion, no-JavaScript fallback,
   console, request-allowlist, and Axe regression suite.
5. Perform final visual review of home, one page from every route family, all
   four product details, Hyper Wallet exclusions, documentation navigation,
   modal, and 404 at the three required viewports and in both themes.

## Final acceptance evidence

The independent test runner must report each exact command, exit code, passed and
failed test counts, skipped tests with reasons, browser retries (required: zero),
and any environment limitation. Completion evidence must include the exact
English sitemap route list, logo/image hash results, root and Pages-base link
crawl summaries, browser request-host inventory, and confirmation of zero
serious/critical Axe findings. Visual inspection must record the reviewed routes,
viewports, themes, and any accepted variance from the pinned template.
